The Studio API exposes the source-checkout prototype described in the [Studio Agent guide](/integrations/studio-agent). Live parameter control uses `http://localhost:8420/api/studio`; independent copied-audio workspaces use `/api/studio/audio` on that same backend. Enable Studio with `MLX_AUDIOGEN_STUDIO_ENABLED=1`; disabled routes return 404. Use a source build containing both Studio workflows and rebuild its matching web UI; packaged builds may have different availability. Check the configured runtime capabilities before execution.

<Warning>
The supplied frozen bridge has passed bounded native quarantine, read-only inspection, denied rearm/write and fresh-connection recovery checks with Live 12.4.15 and Max 9.2.0 on a paused, disposable Set. See the [Studio Agent guide](/integrations/studio-agent) for the exact device and qualification scope. The wider musical-agent workflow remains unfinished, and copied-audio qualification covers a separate boundary. All mode, permission and working-copy checks still apply. Use a disposable, saved working Set. A successful HTTP response can mean a command was queued, not that Live applied it. Confirm the command outcome before proceeding.
</Warning>

## Local access

Studio requires a direct loopback connection, a local Host and an allowed browser Origin. It rejects proxy metadata such as `Forwarded`, `X-Forwarded-For` or `CF-Connecting-IP`. Do not expose Studio through a proxy or tunnel: stripped forwarding metadata cannot be distinguished from a direct native client.

The default allowed browser origins are `http://localhost:8420`, `http://127.0.0.1:8420`, `http://[::1]:8420`, and the same three hosts on the web-development port `3000`. Matching includes scheme, host and port. Arbitrary localhost ports, `null` origins and wildcards are not accepted. A configured backend port replaces its default server-origin port; the Studio Max device's initial default remains `127.0.0.1:8420`.

Native clients can omit Origin. Bridge routes additionally require an in-memory `X-Studio-Bridge-Key` and reject browser Origin headers. The supplied Node bridge manages that credential; never put it in a URL, saved settings, source code or logs.

Send JSON with `Content-Type: application/json`. Requests reject unknown fields, nonfinite numbers and bodies larger than 1 MiB. UUIDs use lowercase hyphenated form; Live object IDs are decimal strings. Errors contain safe codes and messages, without filesystem paths or credentials.

## Endpoint index

Paths below are relative to `/api/studio`.

| Method | Path | Result |
|---|---|---|
| `GET` | `/capabilities` | Supported modes, actions, editable device classes and limits. |
| `GET` | `/sessions` | Session summaries, including connection and copy-confirmation state. |
| `GET` | `/sessions/{session_id}` | Session detail, inventory, plans, commands and checkpoints. |
| `PATCH` | `/sessions/{session_id}` | Updated mode, permission and budget. |
| `POST` | `/sessions/{session_id}/plans` | Immutable numeric parameter plan. |
| `POST` | `/sessions/{session_id}/execute` | HTTP 202 and a command admitted for execution. |
| `POST` | `/sessions/{session_id}/rollback` | Inverse plan for an eligible confirmed checkpoint. |
| `POST` | `/sessions/{session_id}/stop` | Updated session; queued work stops, dispatched work becomes unknown. |
| `POST` | `/sessions/{session_id}/reconcile` | HTTP 202 and a read-only inspection command. |
| `POST` | `/bridge/register` | Session identity and bridge lease/poll settings. |
| `POST` | `/bridge/inventory` | Accepted inventory revision. |
| `POST` | `/bridge/poll` | One command or `null`, plus lease settings. |
| `POST` | `/bridge/results` | Recorded command outcome. |

Each fresh connection generation, called an **epoch**, creates a new session ID when the bridge registers. Reconnecting creates a new session rather than changing the epoch inside an existing session. The old session keeps its commands, checkpoints and unknown outcomes. There is no separate browser endpoint for creating a session or setting copy confirmation.

## Read capabilities and sessions

```bash
curl http://localhost:8420/api/studio/capabilities
curl http://localhost:8420/api/studio/sessions
```

Capabilities identify the planner as `deterministic_parameter_v1`, advertise all four modes, and limit editable device classes to `StereoGain` (Utility). A plan has one action; its runtime cannot exceed 120 seconds. Automatic Live save-copy/rendering and Studio cloud inference are unavailable. Copied-audio rendering has a separate capability and qualification boundary below.

Session detail includes:

| Field | Meaning |
|---|---|
| `id`, `bridge_id`, `epoch` | Current session and connection identities. |
| `revision` | Integer starting at one; use it in modifying requests. |
| `mode`, `policy`, `budget` | Saved authority and limits. |
| `bridge_connected`, `copy_confirmed`, `blocked_reason` | Whether live action is currently eligible. |
| `inventory` | Observed tracks, devices, parameters and transport state. |
| `plans`, `commands`, `checkpoints` | Retained proposals, outcomes and confirmed parameter history. |

An offline session can still have historical inventory. Stored data does not re-establish a live connection or copy confirmation after a restart.

## Set mode, permission and budget

Send all configuration fields to `PATCH /sessions/{session_id}`:

```json
{
  "expected_revision": 1,
  "mode": "collaborate",
  "policy": { "allow_parameter_edits": true },
  "budget": { "max_actions": 1, "max_runtime_seconds": 60 }
}
```

`mode` is `guide`, `collaborate`, `agent` or `full_auto`. `max_actions` must be `1`; `max_runtime_seconds` is an integer from 5 through 120. The update advances the revision and invalidates earlier plans. Updates cannot bypass an unknown outcome or alter policy while a command is queued or dispatched.

Guide never writes. Collaborate requires approval of the exact plan. Agent and Full Auto can execute the selected one-action numeric goal without a separate approval digest, but still require the edit capability, current Max-side copy confirmation, supported target, paused transport and available budget.

## Create a parameter plan

Send `POST /sessions/{session_id}/plans` with the current revision and IDs from that session's inventory:

```json
{
  "expected_revision": 2,
  "objective": "Try a lower value on the selected Utility control.",
  "track_id": "12",
  "device_id": "43",
  "parameter_id": "44",
  "value": 0.65
}
```

The IDs and value above are illustrative. Use the discovered parameter's actual range and native units; do not infer a parameter mapping from its position or from this example. `objective` is a note, not an instruction interpreted by a musical planning model.

The returned plan includes `id`, `digest`, `base_revision`, `epoch`, `inventory_sequence`, `policy_digest`, `target`, `expected_value`, `value`, `kind`, `rollback_of` and an explanation. The server derives target identity and metadata from inventory. A request cannot supply arbitrary executable metadata.

The plan binds its exact target, values, current authority and context. Numeric comparisons use `target.value_tolerance`, calculated as `max(1e-7, 1e-6 × parameter_range)`. Identity and metadata comparisons remain exact. Planning rejects unsupported targets, out-of-range values and no-op changes.

## Execute an approved plan

Send `POST /sessions/{session_id}/execute`:

| Field | Value |
|---|---|
| `expected_revision` | Current revision matching the plan's context. |
| `plan_id` | The returned plan UUID. |
| `idempotency_key` | A new UUID for this request. Preserve it for an identical retry. |
| `approval_digest` | In Collaborate, the exact returned digest after the user approves that preview. Otherwise omit or use `null`. |

The response is HTTP 202 with a command. Poll `GET /sessions/{session_id}` to observe its outcome. Do not equate HTTP 202 with an applied edit.

Only one command may occupy a bridge's mutation slot. The same plan cannot enqueue a second operation under a different request key. Repeating the same request key and payload returns its original operation; changing the payload under that key produces a conflict.

## Command states

| Status | Meaning |
|---|---|
| `queued` | Durable intent exists; the bridge has not received the command. |
| `dispatched` | The command was handed to the bridge; its effect is not yet confirmed. |
| `applied` | Matching command acknowledgement and pre/post readback were recorded. |
| `rejected` | The command did not write; inspect its reason, such as `cancelled` or a changed target. |
| `unknown` | The command may have affected Live, but the result is not confirmed. Further writes are blocked. |
| `observed` | A read-only inspection completed. This does not attribute a previous change. |

Command views include the command ID, target, deadline, status, observed before/after values, reason and related plan/checkpoint identity. They also include these server-derived inspection fields:

| Field | Meaning |
|---|---|
| `inspection_available` | Whether an inspection can currently be queued; not a guarantee that the later read will complete. |
| `inspection_unavailable_reason` | `null` when available; otherwise `not_unknown_write`, `original_generation_unavailable`, `target_changed` or `command_in_flight`. |

These fields are public views, not persisted command authority or fields accepted in bridge commands. Confirmed edits append immutable checkpoints. A checkpoint records one parameter operation, not a saved Set.

## Stop a session

Send `POST /sessions/{session_id}/stop` with `expected_revision` and a new `idempotency_key`. The response is the updated session.

Queued commands become rejected with reason `cancelled`. A dispatched command becomes unknown because stop cannot prove that Live has not already changed. The session is disarmed; use the Max device's reconnect flow before granting fresh authority. Stop never invokes global Undo.

## Inspect an unknown result

Inspect only when the public command view reports `inspection_available: true`. Send `POST /sessions/{session_id}/reconcile` with `expected_revision`, the unknown `command_id`, and a new `idempotency_key`. This queues an `inspect_parameter` command for the original target; it does not resend the write.

A healthy original connection enters read-only quarantine after an unknown write. Node and Live independently refuse parameter writes, clear copy confirmation and complete a bounded quarantine handshake before forwarding another command. An inspection can queue while that handshake is pending. The service checks the original target's structural identity and may use a newer inventory sequence from the same epoch; the current numeric value may differ.

Stop, handshake failure, hard disconnect or reload disarms the original generation. Inspection then becomes unavailable. A fresh generation cannot map old target IDs into its own session or inspect an old command through `/reconcile`.

An observation never clears the write block, turns the old result into `applied`, or creates an inverse checkpoint. Mode changes, refreshed inventory, physical confirmation and matching values cannot rearm quarantine. Any later write requires reconnecting into a new epoch and session ID, fresh physical copy confirmation in Max, current inventory, and a new policy and plan. Historical unknown outcomes remain unknown in the old session.

## Restore a confirmed checkpoint

Send `POST /sessions/{session_id}/rollback` with `expected_revision` and `checkpoint_id`. It returns a plan; it does not write immediately. Execute that inverse through the normal approval and permission checks.

Only the latest eligible confirmed checkpoint in the current epoch can be inverted. Its expected value is the acknowledged post-edit value, and its requested value is the recorded pre-edit value. Detected target or value interference prevents restoration. An inverse appends history rather than deleting the original checkpoint.

## Copied-audio workspaces

The `/api/studio/audio` namespace has independent workspace policy and selected-head revisions. It does not reuse Live epochs, grants or rollback authority. It preserves exact imported WAV bytes, per-channel measurements and immutable retained evidence. The normal UI/API/codec workflow has passed isolated qualification for the tested Mac/Colima/image/asset-root combination; no backend configuration was installed or deployed by that test.

### Runtime eligibility

`GET /api/studio/audio/capabilities` advertises `automatic_asset_render` only for a normal-mode runtime with a deliberately accepted qualification binding, matching reviewed manifest hash, current identity/preflight checks and completed recovery. The binding pins the exact normal profile, image/source, daemon, kernel, seccomp, asset root/device and capability version. Missing/stale evidence or drift blocks admission. Temporary capacity and an unresolved worker are not permission to widen the profile.

`qualification: true` and internal developer qualification sessions always advertise product capabilities false. A local profile, injected `qualified` boolean or successful preflight is not acceptance. Operator configuration uses `MLX_AUDIOGEN_STUDIO_AUDIO_PROFILE` with the closed `profile` and `qualification_binding` objects; optional `MLX_AUDIOGEN_STUDIO_AUDIO_ROOT` must match the accepted root/device. These are trusted local startup inputs, never HTTP fields. No request installs Docker, builds/pulls an image or mints a qualification receipt. See the [operator prerequisites](/integrations/studio-agent#work-with-copied-audio) and the matching checkout's qualification matrix.

`automatic_live_capture`, `automatic_live_render`, `automatic_save_copy` and `automatic_live_apply` remain false. No Studio model/cloud request or musical-quality evaluation follows from audio enablement.

### Closed operation flow

Use the following groups rather than the Live `/sessions` endpoints. All paths in this list are relative to `/api/studio/audio`:

- `GET /workspaces`, `POST /workspaces`, `GET /workspaces/{workspace_id}` and `PUT /workspaces/{workspace_id}/policy` inspect/create the workspace and update its revision-checked policy.
- `POST /workspaces/{workspace_id}/imports`, `/runs`, `/comparisons` or `/selections` creates one exact proposal for `import`, `candidate`, `comparison` or `selection`; proposal responses are HTTP 201.
- Import execution is one raw `PUT /workspaces/{workspace_id}/operations/{operation_id}/body` with `Content-Type: audio/wav`. Other kinds use `POST .../execute`. Both return HTTP 202 and an Operation after durable admission/handoff. Neither status promises completion.
- `GET .../operations/{operation_id}` reads status when granted. `POST .../cancel` uses `expected_operation_digest`, returns HTTP 202, and requests cancellation without claiming confirmed exit. Stop polling when hidden, cancelled, terminal or expired; never renew a deadline or automatically replay an effect after transport loss.
- Workspace `/assets`, `/operations` and `/history` retain discoverable evidence. Asset/operation pages contain at most 50 items and an opaque `next_cursor`; history retains up to its bounded 500-entry budget. `/assets/{asset_id}`, `/assets/{asset_id}/content` and `/comparisons/{comparison_id}` expose owned metadata, verified WAV content and comparison facts under their read grants.

IDs must belong to the URL workspace. No URL/path input, arbitrary codec options, cloud credential or generic tool dispatcher is accepted. JSON keeps its existing 1 MiB bound; the raw import stream has its own guards and limits before body reads.

An import proposal binds `request_key`, `expected_policy_revision`, `expected_head`, `declared_sha256`, `declared_bytes` and bounded provenance. The body must be the exact approved bytes: WAV PCM16/24/32 or FLOAT, mono/stereo, 8–96 kHz, nonempty through 120 seconds and at most 100 MiB. A body is durably claimed once. Repeated bodies are rejected before reads; an interrupted stream needs a new authorized proposal/key. Identical proposal retries return the original operation; a changed proposal under the same key conflicts. Request keys contain 1–128 ASCII letters, digits, underscores or hyphens.

Collaborate execution echoes the exact approved digest: `approval_digest` in the execute body, or one `X-Studio-Approval-Digest` header for raw PUT. Other modes still need their saved independent grants. Proposal approval includes source hashes/length, objective, expected head/revisions, budget/deadline and the returned `output_scope`; preserve these values instead of reconstructing their digest.

### Authority, evaluation and selection

The four audio grants are `import_analyze`, `audition`, `create_candidate` and `select_asset`; all default false. Guide can import/analyze and audition with those grants but cannot create candidates or select. Agent and Full Auto candidates require a saved matching source/objective grant, 1–8 finite attempts and an expiry at most 120 seconds ahead. A consumed attempt or expired grant does not renew on refresh, retry or execution. New authority requires explicit operator action. Changing mode grants nothing.

`sample_peak_ceiling_v1` takes an explicit `ceiling_dbfs` and `minimum_gain_db`, both in [-60, 0]; no production target is chosen for you. Rendered candidates require candidate and audition grants because the same operation creates FLOAT evidence plus its common PCM24 A/B pair. `select_on_accept` additionally requires selection authority. The returned v2 output scope binds those outputs and full equal windows before approval. Already-satisfied, unsupported or no-safe-candidate outcomes create no candidate. Encoded sample-peak acceptance is separate from selection and from musical preference; measurements are not LUFS or true peak.

Standalone comparison proposals bind both asset IDs/hashes, explicit equal-length source-frame windows and `common` or `rms_matched`. Matching only attenuates the louder aggregate RMS; no boost or per-channel gain is allowed. Separately hashed PCM24 derivatives are audition-only. Playback starts paused; browser resampling is disclosed and never becomes evidence measurement.

Selection/restore binds target hash and the expected selected head/revision. Initial selection chooses an imported source; later selection requires an accepted candidate. Restore names a retained predecessor selection event. It appends history and performs no inverse DSP, Live mutation or deletion. A head conflict can leave accepted evidence unselected. Policy revocation cancels pending authority; it does not erase historical evidence or pretend that already committed effects were undone.

Metadata/content reads are independent of selection authority: source/candidate evidence and operation/selection history need import/analysis permission; derivatives and comparisons need audition permission. A selection-only client may submit known retained IDs/hash and read the current workspace head, but cannot fetch forbidden operation/history/content reads. A changed head alone does not prove that operation's outcome; report detailed outcome unavailable when read authority is absent or revoked.

Public `expires_at` values are timezone-qualified RFC3339, canonicalized to UTC with exactly six fractional digits and `Z`; input accepts at most six fractional digits. Echo an existing deadline exactly. Internal identity uses integer microseconds, not a newly derived floating timestamp. Queue/setup/work consume the original deadline. Upload is bounded to 60 seconds, compute to 120 seconds, with one active compute worker and at most two queued operations; ambiguous termination retains ownership and capacity.

Audio errors add nullable `operation_id` inside the existing `error` envelope. Check `error.code`: examples include `policy_denied`, `approval_required`, `stale_revision`, `body_claimed`, `selection_conflict`, `content_mismatch`, `capacity_exhausted`, `worker_blocked` and `storage_unavailable`. HTTP 503 here does not necessarily mean a Live bridge is offline. Inspect durable state after uncertain delivery; stopping a local HTTP request is not a server cancellation or a retry authorization.

The matching prototype checkout's `specs/00002-studio-audio-candidates/contracts/openapi.yaml` and `specs/00002-studio-audio-candidates/contracts/semantics.md` define the full closed fields and bounds. Local audio recovery/selection never clears Live UNKNOWN; every automatic Live capability remains unavailable.

## Bridge protocol

Use the supplied Max/Node bridge for Live control. A custom bridge must preserve these boundaries:

- Registration sends a bounded inventory and an ephemeral credential. A fresh epoch starts in Guide with edits denied. Copy confirmation comes from the Max device, not a browser request.
- Inventory has an increasing `sequence`, `is_playing`, `copy_confirmed`, `truncated`, and nested normal-track/top-level-device/parameter observations. Publishing changed inventory advances the revision and invalidates plans.
- Polling renews an existing lease; it does not recreate expired authority. A queued command is durably marked dispatched before it is returned and is never blindly redelivered. A poll response has required boolean `read_only`: healthy quarantine returns `read_only: true` with `disarm: false` and only inspection commands. `disarm: true` takes precedence and requires a full reset.
- Results identify the bridge, epoch and command, with status, finite readback values and a fixed reason code. Identical acknowledgement retries are safe; conflicting results are rejected.
- A locally unknown result or a service acknowledgement recording `unknown` immediately latches write refusal in both endpoints. The matching `quarantine(epoch, nonce)` / `quarantine_ready(epoch, nonce)` handshake must finish within three seconds before another command is forwarded. Invalid, mismatched or missing acknowledgement fully resets the bridge. Result acknowledgements remain exactly `id`, `epoch`, `status` and `reason`.
- Reload or reconnect rotates the epoch, creates a new session ID and clears confirmation. The bridge rejects callbacks from an earlier epoch and deduplicates command execution within its current epoch. A Node-only restart requires full device reload.
- A failed write or failed readback is unknown unless the bridge can establish that no write occurred. It cannot report rejection merely because an acknowledgement was lost.

The bridge exposes no arbitrary LiveAPI method, shell, filesystem or network dispatcher. Inventory limits are 64 tracks, 256 devices, 2,048 parameters and 1 MiB for the complete serialized UTF-8 inventory, including its identity and metadata fields. The inventory itself is the HTTP request body; there is no additional HTTP JSON wrapper. Truncated inventory is read-only.

## Errors and retained history

Errors use this envelope:

```json
{
  "error": {
    "code": "stale_revision",
    "message": "Refresh the session before continuing."
  }
}
```

| Status | Common cause | Client response |
|---|---|---|
| 400 / 413 / 422 | Malformed, oversized or unsupported input | Correct the request; do not widen target scope. |
| 403 | Local-access, permission, copy-confirmation or approval failure | Restore the required authority through its normal UI. |
| 404 | Feature disabled or object not found | Check enablement and the current session ID. |
| 409 | Stale revision/plan, conflicting replay, busy bridge or unknown result | Refresh state; inspect an unknown outcome only while available, then reconnect and re-enroll before any later write. |
| 429 | Action/time/history budget unavailable | Inspect limits; do not retry a dispatched action. |
| 503 | Bridge offline | Reconnect in Max to create a fresh session. Historical outcomes remain in their old sessions; inspection of an ended generation is unavailable. |

Direct local Studio requests are exempt from the server-wide IP rate limiter. The Studio budget errors above use the `error.code` envelope. Forwarded or proxied requests are unsupported and rejected by the local-access guard.

History is limited to 500 logical journal entries or 16 MiB of canonical history per session. Admission reserves capacity for the command's complete outcome and recovery records before dispatch. Later evidence uses that reservation; old history is not silently evicted. The limit excludes SQLite page and journal-file overhead.

After a server restart, queued commands are rejected and dispatched commands become unknown. No live lease, credential or copy confirmation survives, and pending work never resumes automatically.
